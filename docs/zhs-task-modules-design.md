### 1.4 神谕：草稿判分（2026-10-17 真机复验，**交卷前的官方确认**）

**接口**：`POST https://appstudent.zhihuishu.com/appstudent/student/exam/getQuestionDoneState`
（老 App 端域，**免签明文表单**；PC 考试应用源码里没有它——它在移动端那套里）。

**契约（逐条真机探得，2026-10-17）**：

| 入参 | 实测行为 |
|---|---|
| `questionIds` | **必填**；JSON 数字数组的字符串。缺 → HTTP 400「缺少必要的参数」；空数组 → `rt:{}` |
| `eid` 喂进去 | **不认**：`fastjson JSONException: parseInt error, field : 0`（它对每个元素 parseInt） |
| `examId` / `stuExamId` | **要数字**（形如 `12345678`，脱敏样例），不是 dohomework 路由里的 8 字符串（形如 `A1b2C3d4`） |
| `userId` | **必填**（CASLOGC 的 `userId`）；缺 → 500 NumberFormatException |

**返回**：`{"rt":{"<数字题号>":{"score":"2","done":"true"}, …},"status":"200"}`

**判分是草稿实况，不是上次交卷的存档**——两次真机对照：存错解 → `score:0`；存正解 → `score:2`（zhs-window → zhs-verify）。
**在重做卷的草稿上同样成立**（2026-10-17 端到端实证：沙箱课第三章 未交→探路→收割建键→重做→套键作答→神谕确认满分→交卷，
清单回读 `state=4 score=100/100`，`redoNum.rt` 0→1）。至此本节无推断项，全部为实测。

**三个入参的合法来源**（全部只读、全部现成）：

| 入参 | 来源 |
|---|---|
| 数字 `examId` / `stuExamId` | `learning/videolist` 每章的 `studentExamDto`：`exam.id` / `id` |
| `userId` | `CASLOGC` cookie 的 `userId`（session.ts 已在读该 cookie） |
| **数字题号** | `student/lookHomework`——**该卷交过一次之后**才下发 |

**由此得到一条决定性事实**：神谕要的数字题号，只在「这卷已交过一次」之后才有；而**需要神谕把关的场合恰好就是这种**——已交未满分的卷、以及探路重做的第二枪。从没交过的卷拿不到题号，但那种卷本来也没有键可验（第一枪就是探路，验不验都得交）。**覆盖是完整的。**

**用法边界（必须写死在注释里）**：本工具只把神谕当**验证器**——喂的是「我自己这张卷、我自己已持有的题号」。
**绝不用它做「试错定位题号」或「逐选项试答案」**——那是 §二十五 已废止的 IDOR 式枚举，不实现、不使用、不产品化。
（历史：`.probe/zhs-sbx-submit/eval-window.js` 是那套手法的脚本，注释里以「神谕」为名的两种用法必须区分。）

### 1.5 考试族的信封与入参（2026-10-17 实现期真机核对，逐条实测）

实现时用刚写好的端点跑了只读核对，**推翻了三条来自二手整理的假设**——列在这里，
因为每一条都会让代码静默做错事：

| 事实 | 之前以为 | 实测 |
|---|---|---|
| **成功码字段** | `code`（像学习族） | **没有 `code`，是 `status`**——字符串 `"200"` 成功；失败是 `"-1"`（字符串）或 `-1`（数字）两形都有。只看 `code` 会让考试族的失败**静默通过** |
| **清单页号** | 1 基 | **0 基**：`pageNum=1` 回空表，`pageNum=0` 才出条目 |
| **作业条目 `state`** | 1 未交 / 4 已交 | 还有 **5**（重做过的那卷，落在「未提交」页签、`score` 为 null）。**判「交没交」看 `flag` 页签，别拿 `state` 猜** |
| **清单分值类型** | 数字 | `score`/`totalScore` 是**字符串**（`"100"`），而 `state`/`meetCourseType` 是数字 |
| **两个题面接口** | 同形 | **互补**：`doHomework` 有 `eid` 无题号，`lookHomework` 有题号无 `eid`。凑齐一份题要两个接口 |

**剩余重做次数的真机抽样**（`3 − redoNum().rt`）：未交卷 → `rt=0` ⇒ 剩余 **3**；
已交一次（含一次重做）→ `rt=1` ⇒ 剩余 **2**。所以缺键的卷（从没交过）**不会被门槛挡住**——
探路重做正是为它们准备的。

**入参来源表**（全部只读、全部现成）：

| 入参 | 来源 |
|---|---|
| 开卷/回顾的 `studentExamId`（8 字符串 t1） | 章节 `studentExamDto.examUrl` 的路由段；与清单条目的 `id` 同一个值 |
| 开卷/回顾的 `examId`（8 字符串 t2） | 同上路由段；与清单条目的 `examId` 同一个值 |
| `schoolId` | 同一路由段（末尾倒数第二段） |
| 数字 `examId` / `stuExamId`（神谕） | 章节 `studentExamDto.exam.id` / `studentExamDto.id` |
| 数字题号（神谕与弹题通道） | `lookHomework` 的 `examBase.workExamParts[].questionDtos[].id` |

### 2.1 分类轴改定：按任务类型四板块（2026-10-17 Ryan 定，**已实现**）

本节上面那版（按成绩构成）落地后被 Ryan 改掉了轴。**下面这版才是现行的**——
别照上面 `学习进度（教程+测试）` 那一行去做。

- **四个板块，按平台自己的顺序**：**教程视频 → 单元测试 → 见面课 → 期末考试**。
  设置页与弹窗**用同一套顺序**（早先「弹窗按紧迫度、设置页按成绩构成」的分工被否；
  `2be49df` 那条「弹窗组内测试在前」随之作废）。
- **可见性**：设置页四板块**恒在**（数据没接入的那块给卡 + 如实一句）；弹窗**只显有活的**，
  空的不用占位。
- **分组轴**（2026-10-17 Ryan 定）：设置页按**板块**分组（四张卡）；弹窗按**课程**分组
  （与慕课同一层，`buildGroup` 一处实现），板块是**组内次序**。同一件事在两页的落点相同，
  分组的层级也相同——两页各一套分组，读的人得学两遍。
- **「活」的定义**（一处写死，待办与计划共用——两处各写一遍迟早漂移）：

  | 板块 | 算活的条件 |
  |---|---|
  | 教程视频 | 有未看的 |
  | 单元测试 | 未动过 ∪ 重做已申请（`state=5`）∪（已交 且 未满分 且 **剩余重做次数 ≥ 1**） |
  | 见面课 | 场次/签到有待办 或 测验有未交的 |
  | 期末考试 | **有这个考试就显**（不看开考窗口），且**算活、进待办** |

- **得分挂「单元测试」板块**，行内写两个口径，免得两个页面自相矛盾：

### 模块 2：答卷执行（写）

- 职责：**单元测试 / 见面课测验 / 期末考试共用一条答卷会话**——
  开卷 → 取题面 → 逐题作答（`saveStudentAnswer`）→ **神谕验证** → 交卷（`submit`）→ 回读确认（清单 state=4）。
  - **落地状态（2026-10-20 复核）：只有单元测试接进了执行**。计划的 `run()` 只分派
    `kind === 'quiz'`（`policy/tasks.ts`），`meeting-quiz` / `final-exam` 这两个 kind 从不被产出，
    所以见面课测验与期末考试今天是**只读展示**（`reads.ts` 的 `readFinalExam` 等），不交卷。
    这一条不是巧合，是 `PRIVACY.md`「考试目前不会被自动提交」的落地依据。
- **作答报文用 `eid` 定位**（真机形态，`.probe/zhs-sbx-submit/eval-close-loop.js`）：
  `saveStudentAnswer` 的 `stuExamAnswer` 是一个 JSON 数组，元素
  `{examId, recruitId, stuExamId, eid, schoolId, deviceId:'', examType:'', fromType:3, answer:'<选项id逗号分隔>', dataIds:'', questionType}`
  ——**题面自带 eid，所以作答全程不需要数字题号**；数字题号只有三处要：建键（弹题通道）、神谕、以及题号台账。
- 入口参数来自两处：课程目录的 `studentExamDto`（v1 videolist 已含）与见面课场次的 `examH5Url`。
- 落点：`packages/platform-zhs/src/policy/execute-exam.ts`；题面/答卷结构归
  `src/exam-paper.ts`（会话状态机：题目序列、作答缓冲、暂存节奏、交卷确认）；
  神谕归 `src/oracle.ts`（纯函数解析 + 一次免签调用）。
- **答卷节奏（真人化，Ryan 定，2026-10-16）**：起卷 → 逐题作答 → 交卷按**真实时间**推进——
  每题之间留出真人量级的间隔（按题量估算总时长），不做"秒交"；
  等待期间照走心跳、可停止（沿用 v1 壁钟等待的设计模式，等待函数按需重建）。
  时间花在"作答过程"上，而不是交卷前的空等。
  - **落地状态（2026-10-20 复核）：未实现**。`execute-exam.ts` 的 `saveAnswers` 是逐题连着发完
    就交卷，中间没有任何间隔（文件里没有 sleep/等待函数）。这条仍是设计，不是事实。
- **交卷前过神谕（Ryan 定，2026-10-17，见 §1.4）**：逐题作答后、`submit` 之前，用该卷的
  数字题号问一次 `getQuestionDoneState`，判据 = **Σ每题得分 == 该卷 `totalScore` 且每题 `done`**。
  - 过 → 交卷。**此时无论剩几次作答机会都交**——这一枪是平台自己确认过的满分，不是赌博。
  - 不过 → **不交**，如实报告哪几题没把握（保住那次机会留给人工）。
  - 题号拿不到（这卷从没交过）→ 跳过验证直接交（那是探路枪，本来就没有可验的东西）。
- 安全闸：**开卷是一次显式动作**（绝不探测性打开）；一份答卷未交卷前不开第二份；
  停止语义 = 不开始新答卷，正在飞的请求落地即止（沿用 v1）。

### 模块 3：答案策略（键优先；2026-10-17 改定案）

> Ryan 口径（2026-10-16 深夜）：答案获取**不用**「必须先在目标卷上提交一次」那套。
> 平台事实（本轮真机实证，FINDINGS §二十六）：开卷题面只给题干/选项 id/`eid`，**题号恒为 null**；
> `eid` 是题目级稳定的 16 字节不透明令牌（与题号无可计算关系，三类假设 0/50）；
> 正解唯一出口是按**数字题号**查的弹题族，而数字题号只在交卷后下发。
> 所以「不先提交」的唯一形态是：**键已经存在**。

- **键（`AnswerKey`）= 正解选项 id 集合 ＋ 题干条目（含正解选项文本）**；两个口径都有真机依据：
  同一份题的选项 id 在多次开卷之间稳定（重做换序不换 id），题干口径用于换副本时兜底。
- **建键三来源，取并集**（全官方、全只读）：
  ① **该卷历史已交**（含重做卷）：`student/lookHomework` 取全题号 →`popupAnswer/lessonPopupExam` 换正解；
  ② **同课副本**（另一 recruit / 公开课）：同 ① 收割——把「探路那一枪」挪到副本上；
  ③ **弹题池**：`popupAnswer/loadVideoPointerInfo` → `lessonPopupExam`（只覆盖视频弹题那一份题，沙箱课全量 82 题，
     与单元测试真题面 0/50 重合——不能用来答单元测试，只能作为该课题目键的一部分）。
  - 真机只读复现（`.probe/zhs-key-replay3`）：清单 → lookHomework（50 题号）→ 通道（50 条）→ 键 78 个正解 id，
    与上一轮交卷后收割的旧键**差异 0/0**。
- **作答（每次开卷一次）**：键套卷面（选项 id 口径优先，题干+选项文本口径兜底）→ **全覆盖 → 逐题作答 → 交卷**
  （这一次开卷里只发生一次提交，没有探路那一枪）。
  离线金样本（`.probe/zhs-sbx-submit/verify-key-flow.mjs`）：第二章首答卷/重做卷 50/50 命中、覆盖率 100%、计划 `answer`。
- **门槛（2026-10-17 定稿；机会算式取自平台源码 `9.c58d6fa5a5050724a831.js:11814`）**：
  - **剩余重做次数 = `3 − redoNum({recruitId, examId}).rt`**——这是平台界面自己用的算式，照用。
  - **已交未满分的卷不重打第一枪**：题号早已解锁，收割建键是纯只读（来源①），直接进重做。
  - **重做已申请（`state=5`）的不再申请一次**（2026-10-17 定案，见 §7-7）：重做早就用掉了，
    再申请是白吃一次机会。这条路（`ExamEnter = 'redoOpen'`）**不问次数门槛**——
    它不花机会，而「过得了神谕的那一枪是确定的满分，剩几次都交」。非客观题由覆盖率判据兜住。
  - 缺键（含从没交过的卷）+ 剩余 **≥2** → 探路重做闭环（首答 → 收割 → `saveCourseTran` 重做 → 定分）。
  - 缺键 + 剩余 **=1** → **不自动**，如实呈现/仅提醒。
  - **「留最后一次」的语义**：机会只在**没把握的一枪**上省着用；过得了神谕的那一枪是确定的满分，
    剩几次都交（§3 模块 2）。这条把「次数门槛」和「可信度」两件事分开，别混成一个数。
  - **非客观题不能走 `saveCourseTran`**：平台在重做前问 `exam/getIsObject({examId})`，
    `rt == 1` 才走重做、否则弹二维码（人工通道）。我们照样先问，非客观题 → 只提醒。
  - 平台自己的文案照抄（不自造）：「你还有 N 次重做机会，重做的分数就是你作业的分数哦」
    「重做次数已用完，不能申请重做」。
- **参数纪律（本轮踩到）**：`lookHomework` 的 `studentExamId`/`examId` 取**清单当前值**
  （`getStudentHomework` 的 `id`/`examId`）；课程目录里 `studentExamDto.examUrl` 的 t1/t2 段**会过期**
  （用旧段实测 `{"msg":"2","status":"-1"}`）。
- **明确不做**（Ryan 定案 + 安全审查）：题号空间枚举（IDOR 式批量提取）、AI 解析（红线）、外部题库（非官方）。
- **边界**：既没有键、也没有副本/历史可建键时，首答探路仍是唯一出路——这是平台把题号锁在交卷之后的
  结果，不是实现选择；对外表述不得说成「已绕过」。
- 落点：`packages/platform-zhs/src/exam-answers.ts`（建键／匹配／覆盖率／计划，**已实现并接线到 index**）
  ＋ `test/exam-answers.test.ts`（12 项）＋ `policy/execute-exam.ts`（答卷会话与重做编排，
  **已实现并接线**：四条入口 `fresh` / `submitted`（申请重做）/ `redoOpen`（接管已申请的卷）/ 缺键探路）。

## 4. 执行流程（逐类）

1. **单元测试**：清单（模块 1）→ 取未提交项 → 开卷（模块 2）→ 收集题面 → 答案（模块 3 的当前策略）
   → 逐题作答 → 交卷 → 回读 state=4。
2. **见面课测验**：场次（模块 4）→ `examH5Url` 解出入口 → 同 1 的答卷会话；截止=课程结束时间。
3. **期末考试**：清单（模块 1）→ 校验开考窗（startTime/endDate）与机会数 → 同一套答卷会话
   （期末走 `doexamination` 路由，与 `dohomework` 的差异——限时、可能的令牌/核验——按交卷
   抓包后的终形处理，§7-1/2）。
4. **见面课**：只展示与提醒（无写动作）。
5. **节奏**：三类答卷的作答过程一律按真人节奏推进（§3 模块 2「答卷节奏」）；
   提交动作即时——用时体现在作答上（Ryan 口径：提交可以快，效果要像真人）。
6. 门与停止：`-12/-10`、旗标、SSO 失效 → 停轮 + 失败留痕 + 「下一步」动作位（沿用 v1 机制）。

## 5. 安全与范围

- **读写范围**：课程勾选 = 读 + 写（现状机制不动）；三门只读课不勾 → 不读不写。
- **开卷副作用防护**：任何读取路径不得"顺手打开"答卷；开卷只发生在执行动作里，且一次一份。
- **不可逆写**：交卷即刻计分。沙箱课先行；每类测试首次上线都在沙箱验证后再放开其他可写课。
- **SSO 失效处置**：考试族/见面课调用遇 302→passport（表现为非 JSON 响应/跨域失败）时，
  抛类型化错误 → 停轮、失败留痕，动作位 = 「打开智慧树登录」（复用 `RunFailureAction` 机制，
  与验证桥的「打开验证页」同一形态）。

     stuExamWeb.js:106-118）。用 5 加密的密文网关解不开，回 **404 + Tomcat 错误页**
