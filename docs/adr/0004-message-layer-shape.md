# ADR 0004：载体消息层保持「一张表 + 响应映射 + 类型桥」，不再合并

- 状态：已采纳｜2026-10-21
- 关联：`apps/extension/src/adapters/*/messages/*`、`src/protocol.ts`、`src/ui-bridge.ts`

## 背景

一条消息在扩展里出现在三处：响应映射（类型契约）、处理器表（实现登记）、
界面桥（类型化发送）。曾考虑合并成单一表以进一步减少登记点。

## 决定

保持三处，但用类型把它们绑死：处理器表 `satisfies { [K in keyof XxxResponseMap]: MessageHandler }`，
界面桥的请求字面量必须属于请求联合；漏登记或写错名字都是 typecheck 错误。
消息协议本身留在 `protocol.ts`（两端共用，避免循环依赖），不塞进平台目录。

## 后果

- 好处：新增消息只写一个命令文件 + 两行登记，且有编译期保证；协议层保持平台无关。
- 代价：登记仍是两处，不是一处；换来的是不需要把 handler 改造成返回值的通用包装
  （会给每条消息加一层无收益的间接）。
- 何时重审：第三个载体也要复用同一套消息时（那说明消息该下沉到 application，而不是扩展）。
