# ADR 0005：不设覆盖率门槛，用行为断言与变异核对代替

- 状态：已采纳｜2026-10-21
- 关联：各包 test/、`.github/workflows/ci.yml`、`docs/review-checklist.md` F 域

## 背景

覆盖率门槛是常见做法，但它奖励「被执行到的行」而不是「被钉住的行为」：
为凑数字补的测试通常是同义反复（调一遍、断言不抛）。

## 决定

不引入覆盖率门槛。质量由三件事保证：

1. 行为断言按域写在对应包的 test/ 下（当前 679 条，且分层、不重复别层）；
2. 关键判据做**变异核对**：把实现改坏，对应用例必须红（本轮 A/B/F 三域都做了）；
3. CI 每次提交跑 lint + typecheck + test + build + 无头冒烟，红即不可合并。

## 后果

- 好处：没有「为数字写测试」的激励；测试数量与真实风险挂钩。
- 代价：覆盖率数值不可见。需要时临时用 `vitest --coverage` 看一次（不进门禁），
  用来发现**整块没人测**的区域，而不是当作通过条件。
- 何时重审：出现长期无人维护的模块、或线上缺陷集中在某包时，对该包单独设阈值。
